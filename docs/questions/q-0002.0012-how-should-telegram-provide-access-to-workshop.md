## Impact

The change adds a local external conversation interface to Workshop. The affected
parts are group request selection, Codex conversation integration, the request
history, task/question changes, Telegram answer presentation and the source/authority
boundary. Existing project contracts retain their meaning and constrain permitted
record changes.

## Hidden edges

Telegram ordinary mentions require receiving group messages and filtering them;
unrelated messages must stay outside agent input and retained history. Telegram
entity offsets, linked accounts and captions need actual request-selection cases.
Separate people must not accidentally share independent conversation contexts.
Agent entry invokes bookkeeping and assignment review; permitted task/question
changes remain distinct from code, architecture and publication authority.
Conflicting edits from operator sessions must not be overwritten. Lost delivery
acknowledgements and restart require durable state and separate outcomes for
record application and reply delivery. The agent-facing presentation
amendment must reach Telegram replies without weakening the inherited workflow.

## Leave alone

Daychi, Cabinet and Knowledge implementations, shared application promises,
existing assignment acceptance and queue order remain outside this slice.
The development harness retains its existing rules with scoped Telegram authority
and presentation at the authored local boundary; general debug output is retained.
Continuous hosting and unrelated group-message retention are outside the first
version. Other sessions' current work is preserved.

## Recommendation

Proceed with one end-to-end HITL slice. The accepted first-version scope is one
demoable outcome; separating transport, agent and journal into different delivery
items would leave each incomplete. Meaningful behavior tests can cover filtering,
isolation, authority, restart and uncertain delivery locally. A final real
Telegram-to-Codex conversation is required alongside those tests.
