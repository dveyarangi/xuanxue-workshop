# q-0002.0012.0002 How should Workshop retain and read imported Telegram history and images?

- **record of** what it intends to become
- **part of** q-0002.0012
- **state** open
- **struck** 0, last 2026-10-15T20:22Z

## Context

The user requested real-group migration with its complete history and explicitly
included images. The supplied HTML export contains 205 actual messages and five original still images,
with no missing referenced attachments. Dates span 28 September to
15 October 2026. The source is prepared privately and has not yet been bound to the real group.

The accepted amendment is in the [Telegram contract](../contracts/telegram-workshop.md#imported-history-and-images).
Implementation extends the existing [telegram-workshop-access](../tickets/01-0020-telegram-workshop-access.md)
slice. The export is private source material and does not belong in Git.

## Impact

Archive storage, full-history reads, scoped image content, Telegram attachment
reception and migration activation are affected. The existing receiver needs the
new history and image tools activated before real-group use.

## Hidden edges

HTML lacks verified account identities and may lack the numeric group identity.
Joined author blocks, reply links, original images versus thumbnails, local path
redirection, import/live overlap and old mentions need explicit handling. Source
images and Telegram credentials remain host-side except for the selected image
content supplied to the model. Old messages must not enter the work queue.

## Leave alone

Project ownership, accepted school contracts, existing write tools and publication
authority retain their meaning. Voice/audio and arbitrary document interpretation
are outside the requested still-image slice.

## Recommendation

Use the existing HTML export without requiring another export format. Retain its
messages and selected image originals privately, provide group-scoped search/read
tools, and join new messages by Telegram message identity. Verify the real group
before binding the archive or enabling its replies. Record actual import and visual
verification separately from parser tests.

## Decision — 2026-10-15

The user rejected permanent import rules: the supplied archive is loaded mechanically
once. Remove the product import command and all bot import instructions. Retain
only full-history search and original-image reading as continuing capabilities.
