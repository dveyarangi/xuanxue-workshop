## Existing decision and new failure case — 2026-10-12

The [accepted explicit exit](../../boundaries.md#accepted-web-wiki-explicit-sign-out)
keeps wiki signed out across reload/reopen until deliberate sign-in, and leaves
Cabinet and other clients signed in. The [accepted handoff](../../boundaries.md#accepted-web-wiki-sign-in-handoff)
puts the reader credential on Daychi and gives the browser a HttpOnly cookie.
The accepted normal exit remains fixed. Its failure/storage behavior was explicitly
left open; the native client's independent secure-storage deletion does not
settle this web case.

[MDN's HttpOnly definition](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie#httponly)
excludes JavaScript access to this cookie. Cookie expiry requires a server response
or user/browser intervention; a disconnected frontend cannot promise to erase it.
If a logout request never reaches Daychi, or Daychi cannot durably invalidate its
session, the server may still recognize that cookie. A local UI flag is not
authoritative server invalidation.

## Tradeoff and acceptance evidence

The accepted policy preserves the HttpOnly/server-custody model and
independent client exit without another authentication mechanism. Its cost is
that a disconnected web UI cannot declare completed server-session logout.
Browser storage failure also prevents an unconditional reload guarantee before
backend acknowledgement. Promising offline server invalidation would require
changing the model, not another frontend flag.

Common proof includes request not delivered, lost success response, failed
server deletion, unavailable Cabinet after successful local deletion, failed
browser marker storage, reload/reopen, two wiki tabs, stale callback/renewal
response, and deliberate new sign-in after confirmed cleanup. A copied old
cookie must be rejected after acknowledged local cleanup. Before acknowledgement,
that server-side rejection cannot be asserted. The failure policy is accepted;
implementation and runtime proof remain pending with the parent web profile.
