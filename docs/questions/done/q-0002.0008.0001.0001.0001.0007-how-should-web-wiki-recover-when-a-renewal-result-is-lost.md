## Existing decisions and failure case — 2026-10-12

The [accepted lifetime](../../boundaries.md#accepted-web-wiki-lifetime-and-renewal)
is 90 days, with renewal during use when age is strictly greater than seven days.
It explicitly left predecessor validity and interrupted/concurrent renewal open
for web. Accepted
[credential storage protection](../../contracts/web-wiki-session.md#accepted-credential-storage-protection)
and [local sign-out](../../contracts/web-wiki-session.md#accepted-local-sign-out-and-failure-policy)
remain fixed. Native recovery is accepted for native, not silently adopted for web.

The reader's concrete failure is that Cabinet issues a replacement, but Daychi
loses the response or cannot durably save it. If that issuance invalidates the
stored predecessor, the reader needs a new handoff despite having just used a
valid session. Retaining a usable predecessor supplies a retry path without
introducing a second credential type or another account owner.

## Existing core and accepted answer — the user, 2026-10-12

At Cabinet `67d5cbd0041daa13c6973b657479e45a6716486f`, the inspected
[grant service](https://github.com/gregoryKot/xuanxue-cabinet/blob/67d5cbd0041daa13c6973b657479e45a6716486f/api/src/native-auth/native-grants.service.ts#L110-L141)
renews by issuing another credential for the same native grant and revokes the
grant rather than only one token. The
[native lifetime/recovery contract](../../contracts/native-account-session.md#accepted-credential-lifetime-and-renewal)
already retains predecessors to their own expiry. This is reusable source/design
evidence, not a web implementation or a new runtime test result.

The user replied "хорошо" to the web recommendation. The complete accepted policy
lives in
[renewal recovery policy](../../contracts/web-wiki-session.md#accepted-renewal-recovery-policy).
It preserves the old credential until its original expiry,
uses it after a lost response/write failure, updates local expiry only after
durable replacement installation, and revokes every credential of that grant on
acknowledged revocation. Concurrent/late results cannot replace another session
or undo completed exit.

The unselected alternative was immediate predecessor invalidation on replacement issuance,
which narrows simultaneous credential validity but requires fresh sign-in after
an uncertain renewal unless a new recovery mechanism is supplied. The accepted
retention model instead reuses the existing lifecycle and keeps expiry/revocation
checks authoritative. Its cost is several valid credentials for one grant; theft
is not detected by renewal alone. Confidential caller authentication and encrypted
server custody remain required. No new reader role, refresh-token service or
persistent retry queue is introduced. The web recovery policy is accepted;
remaining wire, implementation and runtime proof belong to the parent profile.
