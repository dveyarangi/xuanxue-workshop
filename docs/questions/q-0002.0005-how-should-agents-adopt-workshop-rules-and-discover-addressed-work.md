### Impact

Workshop readiness touches its startup instructions, the new review skill,
canonical contract, README entry and GitHub interaction. Each project installation
touches only that project's agent configuration and skill, performed by its own
operator and agent. The complete path crosses the Workshop tracker without
creating additional boards or copying shared agreements.

### Hidden edges

The Workshop repository is private and empty; recipient access and publication
are prerequisites that local documentation cannot prove. Startup instructions
must retain the existing recall obligation. A project agent may close an issue
before Workshop review, so discovery cannot examine open issues alone. Local
skill registration depends on the recipient's actual host; a file existing does
not prove invocation. The old README prohibition on agent setup was amended at
its authored local-rule source to support the accepted bootstrap.

### Leave alone

the broader horizon; each project's independent operator and release workflow.
No new background polling service, duplicate success issues or required Workshop
harness installation in sibling projects.

and verify installation results before those tasks are dispatched; the two local
project installations are independent and require separate evidence. Additional
application-contract work remains separate from this onboarding breakdown.
