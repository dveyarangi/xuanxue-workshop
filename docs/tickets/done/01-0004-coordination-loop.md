## What to build

Provide one coordination entry that routes new shared work, changed project
evidence and issue findings through the appropriate stage and resumes interrupted
work without repeating completed investigation. Separate scoped project analysis,
boundary reconciliation and assignment production while retaining the existing
ongoing assignment review. This makes shared standards and provider/consumer
integration use the same coordination path with their distinct acceptance needs.

Give the coordinator one shared validation authority for clarity, consistency,
completeness and contract shape. Apply its requirements at inception and validation,
including direct stage invocation, so no stage silently loses an obligation.
Observations preserve provenance and unknowns; reconciliation preserves agreed
promises; decomposition retains every in-scope responsibility; recipient briefs
are actionable without Workshop session knowledge. Existing internal project
freedom and all contract-shape dimensions remain intact.

Each recipient ticket and its accessible immutable references supply enough
context for independent implementation. Two implementations satisfying their
respective tickets must agree on every shared contract shape and guarantee.
Context completeness and verification of this convergence are required work;
process simplification cannot weaken them or replace them with assumed session
knowledge.

Review issued work for blockers, questions, changed evidence and prerequisites,
as well as completion. Route findings back to the affected stage and maintain
the existing issue. Verify results against their requirements, reconcile records
and reassess dependents without confusing publication, implementation, deployment
or acceptance.

Keep the process proportional to the work. Reuse current evidence and records;
ordinary factual corrections require no new ticket or RFC. Stages do not create
additional approvals, reports or agent sessions. Preserve the existing decision
and publication checkpoints and retain useful rules when extracting instructions.

## Acceptance criteria

- [x] (2026-10-06) A fresh invocation and an interrupted/resumed pass select the appropriate
  stage, preserve earlier evidence and avoid recursive review or duplicate work.
- [x] (2026-10-06) Scoped observations identify the inspected repository revision, coverage,
  supporting evidence and unknowns without inferring deployment from source.
- [x] (2026-10-06) Reconciliation correctly distinguishes no action, record correction,
  correction under an unchanged contract, unresolved decision, migration,
  missing evidence and deferred work.
- [x] (2026-10-06) Shared validation reaches each applicable stage, including direct invocation;
  no existing shared-contract guarantee or ownership restriction is lost.
- [x] (2026-10-06) Independent recipient and issue-set review accepts compatible complete
  briefs and rejects conflicting meanings, omitted obligations, unusable references
  and dependence on Workshop conversation history, including after meaningful edits.
- [x] (2026-10-06) Each side can implement from its own ticket and cited authority without
  private clarification; a counterexample where both satisfy their briefs but
  disagree on a shared shape or guarantee blocks publication.
- [x] (2026-10-06) Ongoing issue review detects a blocker before completion, follows timeline
  references, reassesses changed dependencies and returns to the affected stage;
  acceptance requires appropriate evidence and reconciled records.
- [x] (2026-10-06) A factual correction within an existing assignment completes inline without
  a new ticket, RFC or stage approval; unchanged evidence produces no duplicate response.
- [x] (2026-10-06) A read-only lesson-pair demonstration and an illustrative shared-standard
  case exercise the loop without changing application promises or claiming delivery.
- [x] (2026-10-06) /verify confirms the governing requirements, structural checks, reference
  portability and independently graded behavior; structural success alone does
  not satisfy semantic acceptance.
