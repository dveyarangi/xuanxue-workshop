## Failed-refresh agreement — 2026-10-04

The user chose active cached reminders over pausing them after a failed refresh.
The [delivery contract](../boundaries.md#accepted-daychi-reminder-delivery) owns
the agreement: keep cached schedule and reminders, and apply received cancellations
or transfers on successful refresh.
An unseen cancellation may still produce a reminder. Pending edits remain preserved.
This is accepted target behavior, not verified Cabinet integration.

The user subsequently corrected the proposed visible-warning requirement: it is
project-owned UX, not a shared boundary obligation. The
[scope-of-authority contract](../agent-contract.md#boundary-scope-and-product-language)
owns the general rule. Boundary alignment and later product-language recommendations
are separate work; no warning or presentation requirement is accepted here.

The user requested both modes through URL parameters: retain count-limited

10, maximum 50); it has no date-window query today. Daychi's existing fourteen-day
coverage is the initial window requirement. Names, interval semantics and other
executable details remain Cabinet's proposal to verify with both consumers.
