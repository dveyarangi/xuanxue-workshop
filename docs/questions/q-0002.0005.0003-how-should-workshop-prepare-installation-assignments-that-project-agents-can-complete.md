## Persistent host access — 2026-10-06

The user requires Workshop communication to work across Cabinet sessions, rather
than depend on a one-session setup, and tentatively identifies Claude Desktop.
The [Desktop reference](https://code.claude.com/docs/en/desktop#start-a-session)
distinguishes Local, Cloud, WSL and SSH execution environments. Desktop alone
does not confirm the preceding cloud-scope hypothesis.

For local execution, GitHub CLI authentication in the agent's actual environment
is the persistent candidate: [gh auth login](https://cli.github.com/manual/gh_auth_login)
stores credentials for later invocations. Repository read and write evidence,
then a real original-issue report, would demonstrate that path; a credential
configured only in another OS/WSL/SSH environment would not. A restricted
environment token or separate MCP credential can still differ from stored CLI
authentication.

For cloud execution, Anthropic's
[Code Projects reference](https://code.claude.com/docs/en/claude-projects#set-up-github-access)
documents persistent project repository lists inherited by new threads and
GitHub App authorization for each repository. That candidate requires Cabinet
work to start through the configured project; it does not grant Workshop API
access to every independently created Cabinet cloud session. Projects availability
is limited by plan and rollout. Multi-repository threads also change which
repository settings reach the thread, so this is a host setup choice, not a
silent replacement of Cabinet's existing configuration. Neither candidate was
applied or tested in the recipient environment.
