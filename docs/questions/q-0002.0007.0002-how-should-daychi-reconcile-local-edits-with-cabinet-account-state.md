## Accepted offline editing — 2026-10-04

The user agreed to offline changes: "we preserve as much as possible".
The [boundary contract](../boundaries.md#accepted-offline-reminder-editing)
owns this decision. Pending edits must survive refreshes and connection failures.

## Accepted preservation rule — 2026-10-04

The user accepted per-choice reconciliation: independent changes survive, while
conflicting changes to the same reminder choice use last-updated ordering.
Removals count as edits. Adding lesson A offline and removing lesson B in Cabinet
must preserve both changes. The boundary contract owns this agreement; it does
not yet select timestamp mechanics. Equal-time conflict handling was subsequently
accepted below.

## Accepted lead-time synchronization — 2026-10-04

The user accepted offline lead-time changes, with the latest edited value winning
independently of reminder selections. The
[lead-time contract](../boundaries.md#accepted-reminder-lead-times) owns this
agreement. Receiving or retrying a selection update must not overwrite an
independent lead-time edit, and vice versa.

## Accepted equal-time conflicts — 2026-10-04

The user accepted keeping Cabinet's stored value when conflicting edits have
exactly equal update times. This applies to selections,
removals and lead time. The boundary contract owns the rule. This does not treat
clock uncertainty as an equal-time conflict or select how timestamps are obtained.
The user's subsequent scope clarification leaves presentation and interaction
design with the implementing project; the deterministic tie result remains accepted.

## Accepted explicit sign-out — 2026-10-04

The user chose to discard unsynced reminder and lead-time edits on explicit
sign-out. The [offline-editing contract](../boundaries.md#accepted-offline-reminder-editing)
owns this exception to pending-edit retention. Discarded edits are not replayed
after signing in again or into a different account; already-accepted Cabinet
state is retained. Connection failures do not count as explicit sign-out.
