Source recheck at Daychi `5f9ba442e04cd5dfa70527b9e670b491c491888c`:
[loadSchedule](https://github.com/sleontenko/daychi/blob/5f9ba442e04cd5dfa70527b9e670b491c491888c/apps/practice-app/src/features/schedule/load.ts)
uses `Promise.any` to race its own API with the school HTML request on native
clients; web excludes HTML. The
[HTML parser](https://github.com/sleontenko/daychi/blob/5f9ba442e04cd5dfa70527b9e670b491c491888c/apps/practice-app/src/features/schedule/source.ts)
constructs fourteen days from a weekly template, derives series/date IDs, marks
all occurrences scheduled and sets `exceptions_verified: false`. This path
cannot itself verify Cabinet cancellations, rescheduling or lesson identities.
The inspected files have no local changes.

The recommendation presented was to retire the school-HTML schedule path at verified
Cabinet cutover; obtain fresh schedule data from Cabinet and retain its cached
data under the accepted failed-refresh rule. This keeps one authoritative live
schedule and lesson identity model. A client with no Cabinet cache cannot obtain
a schedule during a Cabinet outage.

Alternative: retain the school website as an emergency source. It can supply a
weekly timetable when reachable during a Cabinet outage, but its exception and
identity limitations require an agreed reconciliation contract and additional
maintenance. It must not silently overwrite Cabinet cancellations or substitute
incompatible occurrence identities for shared reminder selections.

## Accepted source disposition — 2026-10-04

The user decided: "remove the source when integration is verified".
The [source-cutover contract](../../boundaries.md#accepted-schedule-source-cutover)
owns the removal condition and its verification obligations. The migration delta
records the future Daychi contribution; this alignment has not issued that
implementation assignment or changed sibling source code. The existing Cabinet
authority and failed-refresh contract remain accepted.
